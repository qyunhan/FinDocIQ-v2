# Finding: same Stage-2 prompt → divergent HTML across Gemini models (2026-06-29)

Two real API calls on `OCBC_NSFR.pdf` (Appendix A Core + SPANNING framing, verbatim,
`response_mime_type="text/plain"`). Same prompt, same PDF — **materially different HTML**.
The deterministic loader (`html_to_cells.py`) must absorb the variance; the prompt should
stay short (Plan 9 principle).

| Aspect | gemini-2.5-flash | gemini-3.5-flash | parser rule |
|---|---|---|---|
| `data-level` | on `<tr>` (per contract) | on the **first `<td>`** | read from either |
| line number | separate first `<td>` column | **prefixed into label** (`"2 Regulatory capital"`) | column OR prefix |
| header merges | `rowspan` (violates "no rowspan") | flat `<th></th>` (correct) | tolerate rowspan |
| section band ("RSF Item") | `<td>` row | **`<th colspan>` row inside `<tbody>`** | accept both |
| shading (`#D3D3D3`) | **2 cells** (missed most) | **~34 markers / 16 parsed** | grey-only; `#F5F5F5` band excluded |
| value accuracy | duplicated row 2 → row 3 | row 3 correct (`-`) | n/a — model choice |

## Tokens (NSFR × 2 periods) — the MinerU yardstick
- 2.5-flash: 1,523 in / 5,068 out / 8,190 think / 14,781 total
- 3.5-flash: 2,345 in / 10,580 out / 13,317 think / 26,242 total

## Decisions
- **Use 3.5-flash for the quality baseline**, not 2.5 (shading + flat headers + value accuracy).
- Keep the prompt lean; harden the parser instead. Optionally pin `data-level` placement and
  line-number-as-column in the prompt to reduce divergence — but the parser already handles both.
- 3.5-flash returns transient **503 "high demand"**; retry with backoff.
